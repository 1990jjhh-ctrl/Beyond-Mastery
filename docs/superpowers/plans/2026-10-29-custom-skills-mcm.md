# Custom Skills MCM (Plan 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SkyUI MCM page "Beyond Mastery" with one section per installed Custom Skills Framework skill. Each section edits `bEnable` and `sPerkSource`, and changes take effect immediately.

**Architecture:**
- **Papyrus is glue.** A Papyrus MCM script calls native functions the DLL registers. All validation, state and INI writing stay in C++ (`CustomSkills::SetSetting`).
- **Plugin file.** A small ESL-flagged plugin, generated by a Python script, holds the MCM quest and its player alias.
- **Compiled script.** The script is compiled locally with the Creation Kit's compiler under Proton's Wine and checked in, because CI can neither run the Creation Kit nor redistribute Bethesda's sources.

**Tech Stack:** C++23 SKSE plugin (CommonLibSSE-NG), Papyrus (Creation Kit `PapyrusCompiler.exe` via Proton Experimental's `files/bin/wine`, which bundles Wine Mono), SkyUI's `SKI_ConfigBase`, Python 3 stdlib (plugin generator, packaging), native C++ and Python tests.

**Spec:** `docs/superpowers/specs/2026-10-29-custom-skills-above-100-design.md` (goal 2, "MCM", and the plugin-file and Papyrus constraints), as amended by the user's decisions recorded in issue #15:
- The effective level is dropped, so the MCM edits only `bEnable` and `sPerkSource`.
- Enabling takes effect live.
- Plain SkyUI script.
- Its own PR.
- The version goes to 1.1.0 after this.

## Global Constraints

- **Branch and commits:**
  - Work on branch `feat/mcm`.
  - Use Conventional Commit titles per `.gitlint`, and end every commit with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - A fix to something this branch introduced is folded into the introducing commit (`git commit --fixup=<sha>` plus `GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash origin/master`).
  - No pushes; the controller pushes.
- **Native functions:** script name `BeyondMastery`, all `global native`. The only setting keys the MCM can change are `bEnable` (`true`|`false`) and `sPerkSource` (`player`|`own`).
- **Plugin file `BeyondMastery.esp`:** ESL-flagged (TES4 flag `0x200`), master `Skyrim.esm` only. It holds one quest, EditorID `BeyondMasteryMCM`, FormID `0x00000800` (the first ESL object ID). The quest is "Start Game Enabled", has script `BeyondMasteryMCM`, and has one reference alias "PlayerAlias" forced to the player (`0x00000014`) with script `SKI_PlayerLoadGameAlias`.
- **Script sources:** in the repo as `papyrus/BeyondMasteryMCM.psc` and `papyrus/BeyondMastery.psc` (the natives' declarations). The compiled `.pex` files are checked in under `papyrus/compiled/`. SkyUI's headers are fetched at build time into `build/papyrus/headers/` and never committed.
- **Without SkyUI:** the DLL and the INI work unchanged; the plugin only produces Papyrus log errors. Without the plugin enabled, everything except the menu works.
- **Game-free headers stay game-free** (`docs/development.md`, "Rules for code").
- **Thread safety:** native functions run on Papyrus VM threads, while hooks read settings on the CSF caller's thread. Every read or write of a skill's `settings` goes through one lock.

## Review Focus

1. **A setting changed in the MCM while the Upgrade box is open:** the box charges the pool it showed when it opened, or refuses. It never charges another pool. Covered by Task 3's test.
2. **An MCM edit that `ParseSettings` rejects, or an unknown skill id:** the native returns false, and the INI and state stay unchanged. Covered by Task 4's test.
3. **CSF present but no skill enabled at startup, then enabled in the MCM:** the limit lifts at once, because the patch is installed whenever CSF 3.2.0 matches. Covered by Task 2.
4. **The generated plugin round-trips through its own parser:** correct record sizes, the ESL flag, and the VMAD script names. Covered by Task 5's test.
5. **Release archives:** the Data-rooted archive contains the plugin and the scripts. The SKSE-Plugins archive can't carry them, and the README says so. Covered by Task 6's test.

### Task 5: MCM script, compile script, plugin generator

**Files:**
- Create `papyrus/BeyondMasteryMCM.psc` and `scripts/papyrus.sh`, which fetches SkyUI's `SKI_ConfigBase.psc` and `SKI_QuestBase.psc` from `github.com/schlangster/skyui` (`dist/Data/Scripts/Headers/`, pinned to a commit SHA) into `build/papyrus/headers/` and compiles both `.psc` with the Creation Kit compiler into `papyrus/compiled/`. Its environment:
  - `SKYRIM_DIR`: the game folder, which holds `Papyrus Compiler/` and `Data/Source/Scripts`;
  - `PROTON_DIR`: Proton Experimental's `files/`;
  - a throwaway `WINEPREFIX` under `build/papyrus/wineprefix`.
- Create `scripts/make_esp.py` (stdlib only) and `tests/test_make_esp.py`.
- Commit `papyrus/compiled/BeyondMastery.pex` and `papyrus/compiled/BeyondMasteryMCM.pex`.

**MCM behaviour:**
- **Page:** `ModName = "Beyond Mastery"`, one page "Custom Skills".
- **No skills found:** if `GetCustomSkillIds()` is empty, a text option says "No Custom Skills Framework skills found."
- **Per skill:** a header with its name, a toggle "Raise above 100" bound to Enabled, and a menu "Perk points from" with "Your perks" and "The skill's own pool". When `CustomSkillHasOwnPool` is false, the menu is disabled (`OPTION_FLAG_DISABLED`).
- **After every change:** read the value back from the natives, so a rejected change shows the real state.

**Plugin generator `make_esp.py`:**
- `build(path)` writes the plugin described in Global Constraints. It's byte-reproducible: fixed timestamps and version-control fields of 0, and form version 44.
- `parse(bytes)` reads back the TES4 header, the masters and the QUST record's EDID, the VMAD script names and the alias forced-ref, for the test.
- UESP's "Mod File Format" pages (TES4, QUST, VMAD for quests with alias scripts) are the format reference. The builder verifies each subrecord layout there.
